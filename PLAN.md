# План: онлайн-запись для мастеров и тренеров в Telegram Mini App

## Context
Тимофей хочет запустить свой окупаемый стартап и одновременно собрать сильный проект для портфолио к стажировке (Innowise / Modsen / Axonsoft).
Идея: мастер (барбер, мастер маникюра, персональный тренер) создаёт в Telegram свою страницу записи, а клиенты записываются к нему в Mini App без звонков и переписки.
Деньги приносит подписка мастеров (ориентир 20–40 BYN в месяц).
Проект новый, пишется с нуля. Стек выбран под текущий фокус учёбы: JavaScript + React.

Рабочее название: **Slotik** (можно поменять). Папка: `D:\работа прога\slotik`.

## Объём MVP (первой версии)
**Мастер:**
- профиль (имя, описание, фото);
- услуги (название, длительность, цена);
- рабочий график по дням недели и выходные дни;
- список записей, отмена записи;
- ссылка для клиентов вида `t.me/SlotikBot?startapp=<masterId>`.

**Клиент:**
- открыть ссылку, выбрать услугу, дату и свободное время, записаться;
- получить подтверждение и напоминания за 24 часа и за 2 часа;
- отменить свою запись.

**Не входит в MVP:** онлайн-оплата клиентом, салоны с несколькими сотрудниками, аналитика, отзывы.

## Архитектура
```
 Клиент / Мастер
       │ открывает Mini App в Telegram
       ▼
 ┌───────────────┐   HTTPS + initData   ┌──────────────────┐     ┌──────────┐
 │ Frontend      │ ───────────────────► │ Backend (API)    │ ──► │ БД       │
 │ React + Vite  │ ◄─────────────────── │ Node.js + Express│ ◄── │ SQLite   │
 └───────────────┘        JSON          │ + бот (grammY)   │     │ (Prisma) │
                                        └────────┬─────────┘     └──────────┘
                                                 │ sendMessage
                                                 ▼
                                      уведомления и напоминания в Telegram
```

| Часть | Технология | Почему |
|---|---|---|
| Frontend | React + Vite + `telegram-web-app.js` | основной фокус учёбы |
| Backend | Node.js + Express | тот же JS, самый популярный вариант для джуна |
| Бот | grammY | простая и современная библиотека для Telegram-ботов |
| БД | SQLite + Prisma ORM | без установки сервера БД (важно при медленном интернете), потом легко перейти на PostgreSQL |
| Тесты | Vitest | проверка алгоритма свободных слотов |

**Модель данных (Prisma):**
- `Master` (id, telegramId, name, description, timezone = Europe/Minsk, plan, trialUntil)
- `Service` (id, masterId, title, durationMin, price)
- `WorkingHours` (masterId, weekday, start, end)
- `TimeOff` (masterId, date): выходные и отпуск
- `Booking` (id, masterId, serviceId, clientTelegramId, clientName, startAt, endAt, status: active / cancelled)

**Ключевая логика: свободные слоты.** Это классическая задача на интервалы, похожая на алгоритмы, которые ты решал на C++: рабочие часы дня минус занятые записи, нарезанные шагом 15 или 30 минут с учётом длительности услуги. Её покрываем unit-тестами.

**Безопасность:** каждый запрос к API проверяет `initData` от Telegram (подпись HMAC-SHA256 токеном бота). Так бэкенд знает, что пользователь настоящий и не подделал свой id. Эта тема часто всплывает на собеседованиях.

**API (черновик):**
- `GET /masters/:id`, `GET /masters/:id/services`, `GET /masters/:id/slots?date=&serviceId=`
- `POST /bookings`, `POST /bookings/:id/cancel`, `GET /me/bookings`
- `PUT /me/master` (профиль), CRUD `/me/services`, `PUT /me/working-hours`

## Проверка (как понять, что работает)
- **Этап 2:** Mini App открывается из бота на телефоне.
- **Этап 5:** `npx vitest`, тесты алгоритма слотов зелёные (граничные случаи: запись в конце дня, пересечения, выходной).
- **Сквозной сценарий:** с аккаунта А создать мастера, услугу и график → со второго аккаунта Б открыть ссылку и записаться → мастеру пришло уведомление, у Б запись появилась в «Мои записи», слот больше не свободен → отмена освобождает слот.
- Напоминание приходит в тестовом режиме (время сдвинуто на несколько минут вперёд).
